AI Maintenance Planning POC Proposed Scope, Assumptions and Limitations This document outlines the proposed approach for delivering a working end-to-end proof of concept within the assignment timeline. The implementation will focus on the assignment's mandatory requirements. Any incomplete items will be reported clearly. 1. Proposed Implementation Scope l Technology stack: Angular, ASP.NET Core Web API, SQLite, and Ollama with a suitable local language model. l Sample data: One fictional plant with five assets, three technicians, spare parts, two maintenance windows, text-based maintenance manuals, and maintenance history. l AI integration: Use the local language model to interpret maintenance requests and support evidence-based planning. l Document retrieval: Retrieve relevant information from text-based maintenance manuals and maintenance history. l Scheduling and validation: Use an explainable scheduling heuristic. Validate task dependencies, technician skills and availability, maintenance windows, and spare-parts availability in application code. l Planning workflow: Support plan alternatives, editing, replanning, reviewer approval, resource reservations, and revision history. l Exports and testing: Provide PDF and JSON exports and test the implementation against the assignment's acceptance scenarios. 2. POC Assumptions l Use reproducible sample data for one fictional plant. l Use defined scheduling time intervals and a simple, explainable scheduling approach. l Start with a small set of text-based maintenance manuals and structured resource data. l Use a role selector to demonstrate Planner, Reviewer, and Technician roles. l Use fictional data only; do not connect to live equipment or external factory systems. l Run the application locally with SQLite for persistence and test reservation consistency and transaction behavior. 3. Known Limitations l Scheduling: The heuristic will aim to produce schedules that meet the defined constraints, but it will not guarantee the globally optimal schedule for completion time or resource use. l Dataset size: The POC will use a small, controlled dataset rather than high-volume, multi-plant data. l Document processing: Text-based maintenance manuals will be supported. OCR for scanned or image-based maintenance manuals will not be included. l Authentication: Enterprise identity management will not be implemented in the POC. l External integrations: ERP/CMMS and live factory-system integrations will not be included. l Production readiness: High availability, comprehensive monitoring, and production-grade security hardening are outside the initial scope. Core requirements: Mandatory requirements such as deterministic validation, persistent storage, reservation consistency, approval workflow, revision history, failure handling, and export correctness will be prioritised and tested as required by the assignment. Production Improvement Roadmap l Move to a production database suited to the expected workload and carry out further performance and concurrency testing. l Add enterprise identity management and role-based authorisation. l Improve document retrieval and add OCR for scanned manuals if needed. l Add monitoring, logging, alerting, and recovery capabilities. l Automate deployment and infrastructure management. l Add ERP/CMMS integration and multi-plant support if required. l Carry out additional security, scalability, reliability, and performance testing. l Document how the solution could be extended to Azure. Azure deployment is not planned for this submission. 5. Deferred / Non-Mandatory Scope l Kubernetes and a microservices architecture. l Multi-agent orchestration or a dedicated agent framework. l A dedicated mathematical optimisation solver. l Azure deployment and complex cloud infrastructure. l Enterprise Single Sign-On (SSO). l Advanced retrieval infrastructure, such as GraphRAG or a dedicated vector database. l Extensive monitoring dashboards. l External system integrations, including ERP/CMMS, and live equipment connectivity. l Predictive failure model is out of POC scope. These items are deferred to keep the POC focused on the assignment's core requirements and timeline. If any item is explicitly mandatory in the assignment, it will be treated as a requirement rather than deferred.
